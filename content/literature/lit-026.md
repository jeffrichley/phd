## What it establishes

This is the paper that gives study 3's architecture its name and its formal apparatus. Its own
one-line definition is the whole of it: "RTA Systems are online verification mechanisms that
filter an unverified primary controller output to ensure system safety." The primary control "may
come from a human operator, an advanced control approach, or an autonomous control approach that
cannot be verified to the same level as simpler control systems designs."

The property that makes it the right frame rather than a loose analogy is stated as the
architecture's defining quality: "the assurance mechanism is constructed in a way that is entirely
agnostic to the underlying structure of the primary controller." That is precisely the position an
envelope check occupies with respect to a learned skill controller. Safety enforcement is
decoupled from performance, so the certifier does not need to understand how the thing it wraps
was produced.

It also supplies the taxonomy, which is the part that lets study 3 be placed rather than merely
described. Monitoring is either **explicit**, defining a trusted region offline as a forward
invariant or control invariant set, or **implicit**, projecting a backup controller's finite-time
trajectory online. Intervention is either **Simplex**, which switches hard from the primary
controller to a backup, or **ASIF**, which gradually and optimally modifies the control signal
subject to barrier constraints expressed as a quadratic program.

And it addresses learned controllers head on rather than by implication. Its Shielded Learning
sidebar maps the two vocabularies onto each other term by term, state to state, control input to
action, controller to policy, cost to reward, and then makes the argument for filtering over
reward shaping: shaping is "difficult to properly weight", can have "unintended impacts on
performance", and "does not guarantee safety during operations." Determining how to include RTA in
the training process is stated as still open.

Worth recording because it is not decoration: this is *IEEE Control Systems Magazine*, the journal
that published `lit-024` in 1992. The claim that learning-based control belongs to the control
literature is demonstrated by the venue publishing its run-time assurance tutorial thirty-one
years later, in the same magazine, to the same readership.

## What to pull

- **The name and the citation for study 3's architecture**, from the field that owns it. A
  certifier wrapping an unverified controller is run-time assurance, and saying so places study 3
  in a control-theory subfield with AFRL involvement and a tutorial in a control journal (RQ3).
- **The agnostic-to-the-primary-controller property**, which is the formal reason an envelope
  check does not depend on how a skill was learned. That is the same openness `lit-025` and the
  §1.6 lineage argument establish from the other direction.
- **The explicit-versus-implicit distinction**, which study 3's envelope check should be located
  against. Coverage as set containment over certified skill cards is region-based and offline in
  the explicit sense, computed once per skill rather than projected per decision.
- **The nuisance-freedom criterion**, that a filter "should not interfere with the primary
  function" unless necessary and that the trusted region should be "as large as feasible." That is
  a named property against which a refusal rate can be argued rather than merely reported.

## Where it stops, in this dissertation's terms

**Its certificate is about states. Study 3's is about coverage.** The safe set is a region of
state space, written at equation 9 as `CS = {x ∈ X | h(x) ≥ 0}`, and the constraint that defines
it is supplied by the designer rather than discovered. The worked example is explicit about that
direction: a constraint on the position state "is imposed on the system, reflecting the
requirement that the system avoid collision". Study 3 certifies something else entirely, a
parametric extent over the dials and a categorical membership over the switches, per skill card,
and then asks whether a requested mission falls inside the library's union.

**Nothing in it treats library coverage as a certifiable property.** Across 79 pages the words
*library*, *skill*, *coverage*, *repertoire*, *competence* and *refusal* do not occur. So the
question study 3 asks is not one this literature has answered and set aside, which is the finding
that matters most here: the contribution survives contact with the field that owns the
architecture.

**The vocabulary collides where the objects do not, and that is a hazard rather than a
coincidence.** The paper uses *operating envelope* for the state-space region the primary
controller is left free to work in: "the constraint set CA and corresponding operating envelope CS
of the primary controller is as large as feasible." This dissertation uses *certified operating
envelope* for a per-skill certificate over task facets. A reader who knows the RTA literature will
arrive at §01 with the state-space meaning already loaded, so the difference has to be stated
rather than assumed.

**The intervention point is different.** RTA alters or replaces a control input inside the loop,
at run time, every step. Study 3's envelope check refuses a mission before it is attempted and
names the facet that is uncovered. Refusing a task is not an operation this framework performs,
and a filter that has replaced a control input has not declined a mission.

**Its machinery assumes what this platform does not supply.** The ASIF constructions assume
control-affine dynamics with `f` and `g` locally Lipschitz, and the offline safe-set computations
rely on Lyapunov functions, barrier certificates, sum-of-squares optimisation for polynomial
dynamics, discretised Hamilton-Jacobi solutions, or computational geometry that "typically rel[ies]
on convexity of the set CA and linearity of the dynamics." An undulating body whose added-mass
coupling changes character across gait regimes supplies none of those in closed form, which is the
same closed-form gap the §1.6 lineage argument turns on.
